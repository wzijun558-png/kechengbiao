# 更新发布流程（GitHub Releases 托管）

版本基线：**v1.0（versionCode 1）**。更新检查与 APK 分发全部走 GitHub，零服务器成本、零维护依赖。

## 结构

| 部件 | 位置 | 客户端如何拿到 |
|---|---|---|
| 更新清单 `update.json` | 仓库根目录（`main` 分支） | `https://raw.githubusercontent.com/<owner>/<repo>/main/update.json` |
| APK 安装包 | GitHub Release 的资产（asset） | 清单里的 `apkUrl`（release 直链） |

> 客户端只在「有新版」时才下载 APK；日常检查只拉几 KB 的 `update.json`，流量可忽略。

## 每次发版步骤

1. **改版本号** `CourseTableApp/app/build.gradle.kts`：
   - `versionCode` 必须 +1（如 `1 → 2`），客户端据此判定“有新版本”；
   - `versionName` 改为新版本（如 `"1.1"`）。

2. **编译 APK**（debug 签名线）：
   ```bash
   ./gradlew :app:assembleDebug
   ```
   > 线上本体为 debug 签名（`CN=Android Debug`），后续更新必须保持同一签名。
   > 本机构建时使用 `C:\Users\l\.android\debug.keystore`（已从 `android-user-home\debug.keystore` 同步，
   > 并备份于 `C:\Users\l\Documents\CourseTable-debug-keystore-backup\`）。换机器构建前先恢复该密钥，
   > 否则新包签名不一致，用户无法覆盖升级。

3. **计算 md5 与大小**（PowerShell）：
   ```powershell
   $f = Get-Item 'app\build\outputs\apk\debug\app-debug.apk'
   (Get-FileHash $f -Algorithm MD5).Hash.ToLower()   # 得到 md5
   $f.Length                                        # 得到 size（字节）
   ```

4. **打 tag 并推送**：
   ```bash
   git tag v1.1
   git push origin v1.1
   ```

5. **创建 Release**：仓库页面 → Releases → *Draft a new release*：
   - Tag：`v1.1`
   - Title：`课程表 v1.1`
   - 说明写更新日志
   - 上传 APK（建议资产名带版本，如 `course-table-1.1.apk`）
   - Publish

6. **更新 `update.json` 并 push**（模板见 `docs/update.example.json`）：
   ```json
   {
     "versionCode": 2,
     "versionName": "1.1",
     "note": "修复周课表时间显示；新增手机日历提醒。",
     "apkUrl": "https://github.com/wzijun558-png/kechengbiao/releases/download/v1.1/course-table-1.1.apk",
     "size": 7017122,
     "md5": "第 3 步算出的 md5"
   }
   ```
   > 顺序要点：**先发布 Release，再更新 `update.json`**，避免“提示新版却下到旧包”的窗口期。

7. **校验**：
   - 浏览器打开 `update.json` 的 raw 链接，确认 JSON 可读且字段正确；
   - 打开 `apkUrl`，确认能触发下载。

## 说明与注意

- **国内可达性**：`raw.githubusercontent.com` 与 `github.com` 在国内可能较慢/不稳；如目标用户全在国内，可后续在客户端加一个「备用 URL 列表」（先试 GitHub，失败再试国内镜像/OSS），成本仍近乎为零。
- **签名一致性**：升级安装要求新旧 APK 签名一致。本项目走 debug 签名线（`CN=Android Debug`），
  请固定使用同一台机器 / 同一份 `debug.keystore` 构建；如需换用正式 release 签名，
  需全体用户先卸载重装一次（出现“应用未安装”即签名不一致）。
- **成本**：GitHub 免费提供 Release 存储与 CDN 流量；对小体量 App 完全够用，无需额外计费。
